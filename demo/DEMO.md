# 5분 데모 시나리오 — 에비던스 데스크

> 한 줄 메시지: **AI 가 쓴 투자 보고서의 숫자를, 사람이 다시 대조하지 않아도 되게.**
> 에이전트가 자료를 찾아 쓰고, 코드가 숫자마다 출처 칸·계산식을 맞춰 두며, 사람은 빨강·노랑만 본다.

실측 소요(2026-10-19 리허설, NVIDIA nemotron-3-super):

| 장면 | 걸린 시간 |
|---|---|
| 섹션 작성(실적 분석) | 약 60초(LLM 2회 — 증감률은 코드가 미리 계산) |
| 문서 검수(초안) | 약 55~80초(서버에서 돌고, 그동안 다른 화면으로 가도 된다) |
| 대화 에이전트 답 | 약 15초 |
| 기록 비서 배치 | 약 5초 |
| 섹션 작성(리스크 요인) | 약 30초 |

---

## 0. 무대 전 준비 (10분 전)

```bash
backend/.venv/Scripts/python demo/make_materials.py
backend/.venv/Scripts/python demo/setup_demo.py
```

- 백엔드 8200 · 프론트 3200 이 떠 있어야 한다(`backend/.env` 의 NVIDIA 키).
- `setup_demo.py` 가 만드는 것: 워크스페이스 'A사 투자 검토'(김민준 팀장 소유 · 이서연 과장 · 박지훈 대리), 자료 4개 + 타 부서 초안(**근거 제외**로 둠), 리포트 'A사 투자 검토 보고서' + 사내 양식. 끝에 찍히는 URL 을 쓴다.
- 로그인: **김민준 팀장**.
- 브라우저 탭 두 개: **탭 A = 리포트 URL**, **탭 B = 원장 URL**. 작성 중에는 탭 A 를 그대로 두고, 원장은 탭 B 에서 보여 준다.
- 붙여 넣을 문장(메모장에):
  - 대화 1: `리스크 섹션에는 금리 1%p 상승 시나리오(이자비용 증가분)를 꼭 넣어 주세요. 숫자는 IR 자료 기준으로 씁니다.`
  - 대화 2: `@에이전트 변동금리 차입금이 얼마이고, 금리 1%p 오르면 이자비용이 얼마나 늘어?`
- 예비: 리허설 워크스페이스 **'A사 투자 검토 (리허설)'** — 실적 분석·리스크 요인이 써져 있고 검수 결과·할 일·팀 기록이 있다. LLM 이 늦거나 실패하면 이쪽으로 넘어가 같은 장면을 보여 준다.

## 1. 문제 (0:00–0:30) — 근거 > 자료

- 말: "운용역은 ChatGPT 로 초안을 받아도, 숫자 하나하나를 원문과 다시 대조합니다. 그래서 시간이 줄지 않습니다."
- 화면: 자료 5개(IR PDF·실적 요약·손익 엑셀·증권사 리포트·타 부서 초안). 초안에는 **근거 제외** 표시 — "검수 대상 초안의 틀린 숫자는 근거로 쓰지 않습니다."

## 2. 쓰기 (0:30–1:00) — 탭 A 리포트

1. 입력창: `실적 분석 써줘` → 확인 카드.
   - 말: "등록한 **사내 양식의 섹션 지침**과 참고할 자료 4개를 먼저 보여 줍니다(초안은 빠져 있습니다)."
2. **다음 → 이대로 작성**. (약 60초 — 바로 탭 B 로)

## 3. 근거 원장 (1:00–1:45) — 탭 B 원장, 작성이 도는 동안

- 화면: 자료의 표 칸에서 뽑은 수치 28묶음. **매출액 2024 = 3,150 / 3,160 '자료마다 다름'** 을 펼쳐 칸을 누르면 원문 표의 그 칸이 강조된다.
- 말: "에이전트는 문장을 지어내기 전에, 자료의 표 칸을 이 원장으로 묶습니다. 증감률은 모델이 아니라 **코드가 원장 값으로 미리 계산**합니다."

## 4. 숫자 확인 (1:45–2:45) — 탭 A

1. 섹션 카드: `근거 대조 21/21 · 코드 계산 6건`.
2. 본문 숫자 **12.5%** 클릭 → 오른쪽 숫자 확인: '계산값' · `증감률(매출액 2024 3,150 억원, 매출액 2023 2,800 억원) = 12.5%`, 입력 수치 칩을 누르면 원문 표 칸이 열린다.
3. 본문 숫자 **3,150억원** 클릭 → 출처 = IR p.1 표 2행 4열(노란 강조). '자료마다 값: 3,150 / 3,160 · 아직 채택 안 함'.
4. 섹션 아래 노란 카드 '자료마다 다른 값' → 3,150 의 **이 값 채택** → 사유 `회사 공시(IR) 기준` → Enter.
   - 결과: 상단 칩 **숫자 21 · 모두 확인**. 말: "사람이 볼 숫자는 빨강·노랑뿐이고, 이번에는 결정 하나로 끝났습니다. 이 결정은 팀 기록에 남습니다."

## 5. 검수 시작 → 대화 (2:45–3:45)

1. 검수 > 문서 고르기 = **A사 투자 검토 보고서(투자전략팀 초안)** → **검수 시작**. (약 1분, 서버에서 돈다 — 바로 대화로)
2. 대화 > 대화·기록: 대화 1 붙여 넣기 → Enter. 대화 2 붙여 넣기 → Enter.
   - 에이전트 답(약 15초): 1,200억원 · 1%p → 약 12억원, **출처 = IR 2쪽**.
   - 오른쪽 팀 기록에는 아까의 채택이 **결정**으로 이미 있다.
3. 기록 비서 **배치 지금 실행** → 후보 '지시: 리스크 섹션에 금리 1%p 상승 시나리오…' → **확인 — 팀 기록으로**.
   - 말: "흩어진 메신저가 아니라, 이 업무 공간의 대화만 업무 기록이 됩니다."

## 6. 검수 결과 (3:45–4:20) — 검수

- 지적 5건: **불일치** 3,200억원(근거 3,150) · 표의 3,200 · **계산 오류** 30.0% → 계산식으로 23.9% · **근거 없음** EBITDA 520억원 · **문서 내부 불일치** 3,200 ↔ 3,150. 일치 8건(변동금리 차입금 1,200억원 포함).
- **지적 모두 고르기 → 담당자 이서연 과장 → 만들기** → 할 일 5건.
- (선택) **Word 메모로 받기** — 원본 DOCX 에 지적이 Word 메모로 달린 사본.

## 7. 다시 쓰기·내보내기 (4:20–5:00) — 탭 A

1. `리스크 요인 써줘` → 카드에 **참고할 팀 기록: 김민준 팀장님이 "리스크 섹션에는 금리 1%p…"** → 다음 → 이대로 작성(약 30초).
   - 결과: "변동금리 차입금 1,200억원, 1%p 상승 시 이자비용 약 12억원 증가[IR]".
2. 마무리 말(작성이 도는 동안): "내보내기는 사내 양식 DOCX 에 그대로 채우고, 원장 엑셀의 계산 시트는 **원장 칸을 참조하는 엑셀 수식**이라 감사 추적이 됩니다. 다음 단계는 회의 대화에서 일정·할 일을 자동으로 제안하는 것입니다."

## 리허설에서 본 변동(당황하지 않기)

- 섹션 첫 문장에 출처 표기가 빠지는 경우가 있다 → 카드에 '확인할 수치 문장 1개'로 잡힌다. "빠진 것도 시스템이 짚습니다"로 넘긴다.
- 검수의 AI 추출은 돌릴 때마다 조금 다르다. 빠뜨린 숫자는 코드가 문장을 다시 훑어 잡고(요약 줄 '코드가 문장을 훑어 더 찾은 숫자'), 지표를 못 읽은 숫자는 '대조하지 않은 숫자'로 따로 보여 준다.
- 홈의 워크스페이스 목록에 같은 이름이 여럿 보일 수 있다(이전 테스트) — 데모는 `setup_demo.py` 가 찍은 URL 로 바로 연다.
- 같은 초안을 여러 번 검수하면 '앞선 검수 대비 — 해소·남음' 줄이 나온다(재검수 장면으로 써도 된다).
